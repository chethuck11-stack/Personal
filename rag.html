1. Documents

RAG starts with a knowledge source. These could be PDFs, web pages, company documentation, support tickets, databases, or any other text.

Knowledge Base
Input

📥 Input

Your raw knowledge source. In a production RAG system this could come from files, websites, databases or APIs.

🎯 Goal

Transform unstructured information into a format that can later be searched efficiently.

2. Chunking

Documents are divided into smaller pieces called chunks. Retrieval usually works better when it can select a relevant passage instead of returning an entire document.

Generated Chunks
0 chunks
Why chunk? Imagine a 100-page employee handbook. A question about leave policy does not require sending all 100 pages to the LLM. Chunking lets the retriever locate the small section that actually matters.

3. Embeddings

Each chunk is converted into a numerical vector. Real embedding models may generate hundreds or thousands of dimensions. This simulator uses a small illustrative vector.

Chunk → Vector
Simulated embedding model
Important: An embedding is not simply a word count. It represents semantic characteristics of text in a mathematical vector space. Similar meanings should tend to produce vectors that are close to each other.

4. Vector Database

The embeddings are stored together with the original chunks. During retrieval, the query vector will be compared against these vectors.

5. User Query

Now the user asks a question. The question is also converted into an embedding so it can be compared with the vectors in the knowledge base.

Ask the Knowledge Base
User input
Key idea: The user's question is not directly searched as a literal keyword. In a semantic RAG system, the query becomes an embedding and the system searches for vectors with similar meaning.

6. Retrieval

The query vector is compared with document vectors. The highest similarity scores become the retrieved context.

Similarity Search
Top K results
Top-K retrieval: A real system might retrieve the top 3, 5, 10, or another number of relevant chunks. Those chunks become the evidence supplied to the LLM.

7. Augmented Prompt

This is where the "Retrieval-Augmented" part happens. Retrieved information is inserted into a prompt before it reaches the language model.

Prompt sent to LLM
Context injection
RAG does not retrain the LLM. Instead, the application dynamically supplies relevant information inside the prompt at query time.

8. Generated Answer

The final stage is generation. A real LLM would use the retrieved context plus the user's question to produce a grounded response.
